How It Works — The Allocation Pipeline

1
Data Ingestion & Cleanup
Upload XLSX/CSV → auto-map 20+ column aliases → filter out-of-range (>50km) → remove zero-coordinates → group by date
2
Outlier Detection
For each shipment, count neighbors within 2km. If <3 neighbors → excluded as outlier. Prevents isolated points from distorting routes.
3
Hub-Centric Angular Clustering Core Algorithm
Sort shipments by angle from hub (like compass bearing). Split into K equal pie-slice sectors — one per SR. 10-pass boundary refinement balances max travel distance. Result: contiguous geographic wedges, zero route overlap.
4
Earnings-Based Fairness Rebalancing Fairness Engine
Per SR: netEarnings = Σ(payout) − (distance × ₹2.5/km). Iteratively swap boundary shipments until all SRs earn within ±₹50. Up to 200 iterations.
5
Route Optimization (TSP + Google Maps)
Nearest-neighbor greedy TSP from hub. Google Directions API for real road routing. Polyline rendered on Leaflet or Google Maps (toggle).
6
Affinity Mode New
Region density analysis (pincode-based). SR-to-region affinity mapping. Compare Standard vs Affinity allocation side-by-side before execution.
7
LM System Integration One-Click Push
Auto Keycloak auth → bulk allocate via LM API (200ms delay) → confirm OFD + create trip. Zero manual steps.
